# 中间地带授权制与第一批候选传感器（正式提案）

> 状态：提案，待用户裁决后实施。
> 裁决链（2026-10-29 对话）：内容层"永不采集"**维持不动**（本地存储不是
> 安全边界：预消化档案单点、研究层外发腐蚀、管道泄漏、过滤公开信息
> 需先读全部信息四个反驳成立）；中间地带从"白名单制"升级为
> **"逐传感器授权制"**——本文即该制度的设计与第一批候选。

## 1. 通用授权机制（跨传感器的基础设施）

**模型**：与全局暂停（is_paused）同构的探针注入——每个中间地带传感器
构造时注入 `authorized() -> bool`，**未授权 = 不启动采集**。不是"采集后
不保存"，是根本不采：无授权前的历史空白是设计结果，不存在追溯补采。

**存储**：`meta['auth.<sensor_name>'] = 授予时刻 ISO`。

**治理**：
- 授权/撤销本身是治理事件 → 发布 `system.daemon/auth` 事件留痕；
- 面板新增"设置区"：`GET /api/auth`（各传感器授权状态 + 会采集什么
  的人话说明）、`POST /api/auth/<name> {grant: bool}`；
- **撤销即焚**：撤销 = 停止采集 + `DELETE FROM event_raw WHERE sensor=?`
  （该传感器全部历史），焚毁事实写入 meta 留痕。授权时可逆，撤权后
  无残余——这是对话中承诺的边界，必须由机制而非纪律兑现。

**默认**：全部关闭。授权动作永远来自用户直接操作（面板开关），
不允许 toast/建议里诱导授权。

## 2. 候选一：域名传感器（`app.web` / `host`）

**信号**：浏览器处于前台时，读取地址栏 → **立即在内存中截断为 host**
（scheme + host，路径与查询串丢弃）→ 仅 host 变化时发一条事件。

**事件**：`{"host": "douban.com", "browser": "msedge.exe"}`。

**技术路径**：UI Automation（UIAutomationCore，comtypes）读地址栏
控件文本；浏览器白名单（msedge / chrome / firefox）外的窗口一律不碰。

**隐私分析（本提案最敏感处，请重点裁决）**：
- host 历史 = 域名粒度的浏览画像——这正是它属于中间地带、需要显式
  授权的原因；
- **瞬态全 URL 是唯一的敏感时刻**：截断发生在内存中，全 URL 永不
  落库、永不进日志（包括 debug 日志——截断纪律写进代码而非注释）；
  用户正在地址栏输入搜索词时读到的文本，截断后只剩 `bing.com`；
- 不碰：页面内容、标签标题、全 URL、搜索词、隐身窗口（浏览器名或
  InPrivate 标记可识别时跳过——细节实施时验证）。

**五问**：本传感器是纯采集（无动作），五问的"动作/纠正信号"两问
**转移到消费场景**考核；"信号结构化 ✓、偏好重复 ✓（浏览模式天天在）"。
其消费场景（合法版电影建议）见 §4，考核结论：**必须走研究层提案档，
不允许任何确定性技能直接消费域名信号出手**——域名只进观察/关联层。

## 3. 候选二：日历忙闲（`calendar` / `busy`）

**信号**：用户自备 ICS 订阅 URL（**提供 URL 这个动作本身即授权**，
无 OAuth 复杂度）→ 本地定期拉取（每日两次）→ 解析时**只取 VEVENT 的
DTSTART/DTEND**，标题/描述/参与人/地点在解析器里直接丢弃。

**事件**：`{"date": "2026-10-30", "intervals": [["18:30","19:00"], ...],
"lookahead_days": 7}`——未来 7 天的忙时块，每日快照。

**红线对应**：方案修订 §6 原文就把"日历忙/闲时段"列为标识中间地带
第一例。约束延续：忙闲只用于判断"有没有安排"，**不进任何通知文案**
（"到点预告只外推行为节律，不断言日历事实"——不会出现"你明早有会"，
只会有"你周五晚上通常没安排"）。

**五问**：同候选一，纯采集；消费场景见 §4。

## 4. 解锁的消费场景（两候选共同支撑）

**场景目录新条目：周末生活提案（研究层，Phase 5）**——
周五 + 临近收尾（节律记忆）+ 近期浏览含影讯/购票域名（域名传感器）+
晚间无安排（日历忙闲）+ 天气 API（研究层外部数据）→ **研究层生成
结构化提案**："今晚适合看电影，要打开购票 app 吗？"（一键跳转 = 拉起
白名单进程；**永不代购**）。

考核：提案档起步（推断永不越过待确认区）；多源稀疏推断正是研究层
agent 的合法领地（§19 界）；启动条件不变——**台账数据说话**。
域名/忙闲传感器先上线采集，属于为 Phase 5 备料，与"现在就能建议电影"
是两回事（顺序纪律）。

## 5. 明确不做（本提案的边界清单）

微信等 IM 的任何信号（窗口标题含联系人名，无法与内容切割）；窗口
标题通道（公开/私密的分界在内容里，过滤器即违规）；屏幕画面；键盘；
全 URL 与搜索词；邮件。**本提案不构成对内容层的任何开口**——
对内容的任何新提案必须先满足前置条件清单（静态加密/传感器沙箱/
外发审计/授权台账/撤销即焚全部就位），那是一次独立的、更重的裁决。

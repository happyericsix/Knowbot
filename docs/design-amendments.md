# 设计修订登记（v0.1 方案 → 实施现实）

> 本文档登记《个人驻留事件Agent-项目方案.md》v0.1 定稿之后，在 Phase 0/1
> 实施与真实数据验证中产生的**全部设计偏差及理由**。每条修订可追溯到
> 具体的实测证据或用户校准。方案 v0.1 原文保持不动（历史定稿），
> 本文件即"现行设计"与它的 diff。

## 1. A2 归因：用户校准落地（2026-10-25）

**校准来源**：用户四问四答（见 docs/phase1-volume-attribution.md §10）。

| 修订 | v0.1 原设计 | 现行 | 证据 |
|---|---|---|---|
| 内容可解释的纠正（A2/A4） | γ_soft=0.8 | **γ_content=0.95**（几乎不罚，锚点照记） | 用户："调音量基本都是适配当时的内容" |
| 归因主窗 | 10s | **30s 三档衰减**（≤2s 原始 / 2–10s soft / 10–30s extended=0.9） | 用户："会出现插耳机一段时间后才调" |
| missed_need 学习窗 | 隐含同主窗 | **单列 c_window=60s** | 同上：晚调也是学习机会 |

哲学落地：**惩罚体系分层**——系统默认"用户在伺候内容，不是在骂 agent"；
只有内容解释不了的调整（A1 安静中嫌响 / A3 内容洪亮仍不够）才配重罚。
锚点无论哪种情况都记（设备映射收敛靠锚点积累，不靠罚）。

## 2. A3 聚合：churn 判定从单设备阈值改为协同指纹（2026-10-25）

**证据**：真实语料（fixtures/audio_monitor_wake.jsonl）——显示器唤醒不是
"一个端点翻 11 次"，而是 **3 个 NVIDIA 端点协同翻转、每路只翻 2 次**。
单设备阈值（正常插拔也是 1-2 次）永远抓不住。

**现行**：churn = 单设备翻转 ≥3 **或** 锚点 ±3s 内 ≥2 个别的端点在翻。
物理含义：一次人类插拔没有邻居；系统级抖动必然多端点同步。

## 3. 记忆衰减：固定半衰期 → 状态门控 + 频率归一

v0.1"两周半衰期"对低频偏好（一周一次的 HDMI 音频）是"还没收敛就遗忘"。
现行：explicit 与高置信 active 不随墙钟衰减；observed/inferred 按**该偏好
自身触发频率**归一半衰期（docs/phase1-memory-ddl.md §3）。

## 4. Skill：九元组 → v1 五元组 + 元数据

v1 白名单只有三个动作、一个音量技能，合成算子无从验证（没有第二个抢
旋钮的技能）。现行：五元组（触发/查询/执行/观察/撤销）+ 风险等级、延迟
预算作为元数据字段；合成算子等出现第二个使用者再实做，接口带版本号。

## 5. 交互：桌宠延后制作，toast + 面板先行

**决策**（2026-10-25，用户定）：桌宠地位不变（方案 §8.1 原样，一等公民），
但排在 Phase 1 之后——先有灵魂（会行动的 agent）再造身体（形象）。
Phase 1 期间：Windows 原生 toast（自带按钮，含三键校准）+ localhost 面板
作为交互的**临时载体**；桌宠上线后气泡功能从 toast 迁移进去。

**交互总原则**（多轮讨论收敛）：
- 高频重复 → agent 自学（零操作）；
- 瞬时决策 → 按钮（toast/气泡，2-3 个预设项）；
- 管理审计 → 面板（可以有输入控件——红线只禁桌宠变聊天窗）；
- 文本指令是最次选，只在"一次性、带条件、无法枚举"时引入；
- **explicit 用户意志永远压过 inferred 统计**；技能可在面板锁定档位
  （如"环境恢复永远停留在确认档"——用户明确要求不升档）。

## 6. 红线细化：标识与内容的三条分界（2026-10-25 讨论）

"听事件不听内容"的精确边界，按数据性质分级：
- **纯标识**（默认采集）：进程名、设备 ID、VID/PID、事件时间戳；
- **标识中间地带**（需显式授权的传感器）：文件路径（MRU 最近文件）、
  日历忙/闲时段——路径与时段本身不是内容，但接近隐私边界，装传感器
  前必须用户点头；
- **内容**（永不采集）：窗口文本、屏幕画面、键盘输入、文件内容、
  会议标题。

推论：到点预告只能外推**行为节律**（"你通常 18:20 收尾"），不能断言
**日历事实**（"明早有会"）——除非用户授权忙/闲传感器，且以问句进
待确认区。

## 7. 关闭应用动作的新护栏（授权升档场景）

用户授权后"关闭耗电应用"可自动执行，但该动作自带三道护栏：
1. 只许优雅关闭（WM_CLOSE），**绝不 TerminateProcess**；应用弹
   "未保存确认"框时代理人不许代点——关不掉的留在清单里告知；
2. 白名单子集：仅限已知有会话恢复的应用（浏览器/IDE 类）；
3. undo 不对称明示：重启 ≠ 无损还原，风险档"低"起步，静默档需
   更长信任积累；例外按应用粒度记（"关 Chrome 可以，别碰 Docker"）。

## 8. 工程修订（不改变设计语义）

- `action_log.exec_mode` 新增 **`none`**：决策为"不出手"也落台账
  （missed_need 的挂靠点，四象限不缺角）；
- 音量观察用 **IAudioEndpointVolumeCallback**（带 context GUID，天然
  区分 agent 写/用户调），不用 OnPropertyValueChanged；
- 归因 N1 噪声判定：首个静止值无 from 时跳过（无法算幅度）；
- config.toml 自动加载；批处理脚本必须 CRLF（LF 会被 cmd.exe 腰斩）；
- Python 3.10 兼容层（wintypes 缺失结构体的自定义兜底）。

## 10. 音量技能双触发源（2026-10-26）

用户场景：**手动切换默认输出（不插拔）**此前不触发技能——但"切到耳机"
与"插入耳机"意图等价。现行触发条件（二者之一，5 秒去重窗防插拔双触发）：
- `device_settled(final_state=active, 非churn, 耳机类)`——插拔定案；
- `default_output(flow=render, role=multimedia, 耳机类)`——手动指向，
  同设备 5s 内已触发过则让路；观察窗占用期间不重复决策。

顺带确认：pre-arm 挂在传感器层 default_changed 钩子上，手动切换同样
享受预埋保护（开关打开后）。

## 11. 评审时提出、尚未采纳的建议（保留跟踪）

- "每应用输入法"从优先名单降级（Windows 自带记忆，TSF 编程切换
  在 UWP 上不可靠）——同槽位候选改为每应用音量（ISimpleAudioVolume）；
- 模型层整体后移（v1 零模型，SFT/DPO 移出路线图直到台账数据说话）；
- localhost 面板绑定 127.0.0.1 + 随机 token。

## 12. 三键校准闭环落地（2026-10-26）

**"刚好"的语义**完全按 memory-ddl §7 走查：evidence(kind=calibration) +
实例级信念诞生/升格（source=explicit、置信 MAX(旧值, 0.9)、state=active）+
锚点照记（一次点击=数周被动观测的兑现）+ 台账回填 accept/correct_detection。

**"太轻/太吵"的语义**（文档此前未定义，本条即登记）：方向性纠正——
置信度 ×γ(0.8) 轻罚、**值不动**、台账回填 correct/false_alarm。理由：
只有方向没有幅度，猜幅度就是学错（哲学 5）；真实幅度交给 A 规则的
锚点机制（用户下次手动调，C1/A 链路自然补值）。护栏：同一台账已有
裁决则拒绝重复校准（双击/两处入口防重）。

**回传通道**：toast 按钮 protocol 激活 → `knowbot:` URI（HKCU 注册，
daemon 启动幂等重写，pythonw 静默）→ `knowbot calibrate` CLI 直写库
（面板关闭也能落）。面板 `POST /api/calibrate` 与之**同一学习器代码
路径**；待确认区草稿与未决台账行也带三键。

**影子周的裁决通道**：dry_run/suggest 出手现在也发 toast 带三键——
影子模式没有真实动作，toast 即交互本体，三键是影子决策质量唯一
的显式裁决入口（周 FA 率的分子来源）。silent 档仍零打扰。通知
每日预算（哲学 9）尚未实做，shadow 周量级可控，后续补。

**工程修订**（不改变设计语义）：
- 台账 `trigger_event_id` 此前恒为 NULL（信封无库 id）——现由技能在
  finalize 时反查 event_raw 回填（观察窗 ≥ flush 周期，事件必已落库），
  证据链"你为什么信这个"补全到原始事件；
- 面板时间戳统一 now_iso()（此前 sqlite datetime() 与 ISO 两种格式
  无法按周窗比较）；周窗四象限统计兼容解析两种历史格式；
- 面板概览新增周窗 FA 率卡片（健康线 <10% 的度量落地）。

## 13. 触发规则：耳机类白名单 → 成为听音输出皆触发（2026-10-27）

**实证**：ZhuAudio ZG2 USB DAC 接耳机日常使用，Windows 报 form_factor=
speakers（USB DAC 的普遍形态），耳机类白名单永远漏掉——2026-10-26 20:32
真实插拔会话验证：事件链完整捕获、STA 修复验证通过（拔出后 215 拍心跳
无缺），但技能零触发、零 toast。用户裁决：接入并成为听音输出的设备
**都应被识别**。

**现行**：意图信号 = "端点成为 render/multimedia 默认输出"（插拔定案或
手动切换，两路各自满足即触发，5s 去重不变）。form_factor 只用于**选类级
先验**（speakers→0.25 / headphones→0.35 / ...），不再做触发闸门。排除项：
- `hdmi`（显示器/电视音频，含 DP）——churn 风暴源头，非个人听音；
- `remote_network_device`（远程桌面虚拟端点）——RDP 接入不是听音意图；
- 缺 form_factor（元信息读取失败）——无信息不触发。

**安全性论证**：当前 dry-run 影子模式，放宽触发的成本只是一次 toast；
内置扬声器/显示器不动默认输出、不会自发触发（实测显示器风暴不产生
default_output）。影子周的周 FA 率仪表正是检验本条修订的数据来源，
超标再收紧。

**已知局限（保留跟踪）**：插拔瞬间伴随的 HDMI 风暴会让协同翻转数虚高，
非 hdmi 端点的 device_settled 被连累标记 churn（ZG2 会话实测 co=4）。
路径二（default_output）不受影响、可兜底，故暂不改 A3 协同指纹语义；
若影子周发现大量触发靠兜底路径，再考虑"co-flip 邻居排除 hdmi"。

**§13 附注（同日，首次真实触发实战修订）**：20:30 ZG2 重插产生首批影子
台账（#1 扬声器触发正确 + #2 麦克风误触）。修正：**capture 端点不是听音
输出**，路径一新增排除（form_factor=microphone，或 flow=capture，或按
MMDevice ID 前缀 `{0.0.1.` 识别——state_changed 元信息不含 flow，前缀是
唯一可靠的就地判别）。触发观察窗占用期内的同设备 default_output 由
观察窗守卫自然去重（实测 20:30:50 的切换未二次出手）。

另：ZG2 为复合 USB 设备（音频功能随 4C4A:4155 枚举，非 1D57:FA93），
此前"插了没反应"是音频接口未随总线上电完成枚举，与传感器无关。

## 14. 停留输出补决策（2026-10-27）

**实证**：20:49 连续 5 轮切换（09→32s），前两轮各 ~2s 出手（管线延迟
正常），中间被观察窗守卫正确压制；但**最终停留的输出**（20:49:32 Realtek）
触发落在自身观察窗内被挡，用户不再切换后永远无决策——"停在哪反而没反应"。

**现行**：观察窗占用期的同设备触发不再丢弃，记 pending；窗到期时若该设备
**仍是 render/multimedia 默认输出**则补一次决策（过期间图作废）。语义：
快速来回切换 = 意图未定不重复出手；停止后的停留输出 = 最终意图，必有决策。
最终决策出现在停轮后 ~30s（= 归因观察窗时长，校准 Q2 的用户自定值），
这是特性不是延迟——观察窗是归因完整性的底线。

**时效校验（同日追加）**：技能直订原始 default_changed 流维护"当前默认
听音输出"（毫秒级真相），**决策瞬间校验触发设备仍是当前默认**——折叠
事件滞后 ~1s，不校验会为已切走的设备决策并弹提示（实测：切到新设备后
toast 仍在说旧设备）。过期触发静默作废，补决策的停留判据同用此真相源。

## 15. pre-arm 上线：台账化 + 暂停覆盖（2026-10-27）

前置条件全部满足（STA 修复验证 ✅、事件链 ✅、触发与校准闭环 ✅），
`enable_prearm=true` 落地。两个工程修订：

1. **台账不可豁免的落实**：pre-arm 原先只发 `audio.device/prearm` 事件、
   无任何台账落账（传感器层不碰记忆库）。新增 PrearmLedger 消费者
   （skills/prearm.py）：skill=prearm / exec_mode=silent / risk=zero /
   undo=前值 / 溯源回填到触发它的 default_changed（落账时事件尚在
   落库缓冲区，延迟 2s 反查）。反应位留空：prearm 无观察窗、对用户
   不可见，纠正信号=面板撤销（撤销即 reject/false_alarm）或下次使用
   该设备时的手动调整（audio.volume 链路自然捕获）——不虚构裁决。
   周窗"待裁决"统计排除 prearm（不可见布防不期待裁决）。
2. **全局暂停覆盖反射层**：暂停的语义是"agent 别动我的系统"，反射层
   不豁免。传感器增加 is_paused 探针（daemon 注入；独立只读连接查询
   meta.paused，不与 store 共享连接避免跨线程竞争；默认切换是稀有
   事件，连接开销可忽略）。

## 16. 计算礼貌落地：影子 toast 节流 + prearm 冷却（2026-10-27 深夜）

**实证（23:10 风暴）**：75 秒内用户来回切换输出约 10 次，产生 12 条台账
（6 影子决策 toast 连环 + 6 次 prearm 真实写音量），且补决策机制（§14）
在观察窗到期后又延迟弹数条——三因叠加形成通知轰炸与写放大。

**修订**（哲学 9"通知有每日预算"从纸面落地，阈值全在 config）：
- **影子 toast 节流**：同设备冷却 600s + 全局日预算 30 条；超限**静默落
  台账**——影子周的数据质量不受影响，只压制打扰。真实执行档（notify）
  不受限（它的通知就是动作语义的一部分）。
- **prearm 冷却**：同设备 300s 内不重复布防（see-saw 防护）。正常听音
  节奏（一次插拔听几十分钟）不受影响；快速测试性切换不再反复写音量。

教训记录：§14 补决策与 prearm 上线当日即遇到"多机制在极端使用模式下的
共振"——影子周读数时要意识到 23:10 这类测试性风暴属于人为分布。

附注（延迟压低）：切换→提示的延迟实测 ≈ 折叠安静期(2.0s) + PowerShell
WinRT 加载(0.5s)。角色切换突发实测 ~300ms 内完成，安静期压到 1.0s
（`agg_settle_s`），总延迟 ~2.7s → ~1.7s。补决策的延迟弹出已由节流静音
（落台账不弹通知），机制本身保留。

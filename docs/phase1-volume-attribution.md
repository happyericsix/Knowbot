# Phase 1 音量归因决策表（A2 入场券）

> 状态：待评审 · 2026-10-25 · 对应方案 §4.5/§6.4 · 依赖 A1（接口已对齐）
> 实现位置：`src/knowbot/attribution/volume.py`（纯函数，规则编号即代码注释）

## 0. 问题：为什么归因是全项目最难的一环

核心循环是"事件→查记忆→适配→**观察修正**→学习"。前四环都有现成技术，唯独归因没有：
你在我设完音量 8 秒后手动调了一下——**这是在纠正我，还是在适配当时那部炸耳的电影？**
判错的方向是死亡螺旋：把内容适配学成设备偏好 → 记忆污染 → 下次错误执行 → 你不再信任。

目标：把"用户为什么动音量"从猜测变成**带证据、带规则编号、可回放验证**的确定性判定。
Phase 1 全部用规则，不用模型——规则可解释、可审计、可单独修正。

## 1. 输入信号（六路证据）

| 信号 | 获取方式 | 可靠性 | 说明 |
|---|---|---|---|
| Δt 时间差 | action_log/事件流 | 高 | 紧随 agent 动作的调整大概率相关 |
| 方向与幅度 | 音量观察事件（响度域换算后） | 高 | 反向=否定我的值；幅度过小=噪声 |
| 电平表 | 窗口内 2Hz 受控采样（IAudioMeterInformation） | 中 | 区分"内容太炸"与"基线太高" |
| **旋钮身份** | master endpoint vs 每应用 session | **关键** | 调 master=设备偏好证据；调某应用的 session=内容适配，**不算设备偏好** |
| agent 是否真出手 | action_log.exec_mode | 高 | dry_run/none/suggest 都不算"执行" |
| 前台应用 | app.foreground | 低 | 仅作上下文存证，不参与判定 |

## 2. 四大场景分流

```
窗口内（默认 10s）有没有"master 音量的静止调整"？
├─ 没有 + agent 真执行了（silent/notify）→ 场景 B：接受 ────────── reaction=accept
├─ 有 ┬─ 调的是 session（应用音量）        → N2：内容适配，不动设备信念 ─ reaction=ignore
│     ├─ 幅度 < 噪声底线                  → N1：微调噪声              ─ reaction=ignore
│     ├─ agent 真执行了                   → 场景 A：纠正（强度分级，见 §3）
│     └─ agent 没真执行（none/dry_run/suggest/无信念）→ 场景 C：Missed-Need + 学习
└─ 窗口外 → N3：自发调整，进观察草稿，不进纠正统计
```

**"静止调整"**：音量滑条拖动会爆发几十条事件（Phase 0 已知），观察层先去抖（settle 1.5s），
只把静止后的最终值作为一次调整上报。

## 3. 场景 A 决策矩阵（核心表）

前提：agent 已把 master 从 `from_L` 设到 `target_L`，用户 Δt 内把 master 调到 `user_L`。

方向 = 用户调整方向 vs agent 调整方向；`active` = 电平表 active_frac ≥ 阈值（有内容在放）。

| # | 用户方向 | 内容在放 | 判定 | 解读 | 置信度动作 |
|---|---|---|---|---|---|
| A1 | 反向·下调 | 否（安静） | **强纠正** | 安静时还嫌响——内容解释不了，铁证 | ×γ_hard(0.5) + 锚点 |
| A2 | 反向·下调 | 是 | 准纠正 | 校准Q1：多半是内容炸，几乎不罚 | ×γ_content(0.95) + 锚点 |
| A3 | 反向·上调 | 是 | **强纠正** | 内容洪亮仍不够响——铁证 | ×γ_hard(0.5) + 锚点 |
| A4 | 反向·上调 | 否（安静） | 准纠正 | 校准Q1：多半是补偿内容太轻 | ×γ_content(0.95) + 锚点 |
| A5 | **同向继续** | 任意 | 方向确认·幅度纠正 | 校准Q3：方向对了但没到位——锚点必记，罚得轻 | ×γ_soft(0.8) + 锚点 |

强度衰减条款（三档时带，校准 Q2 落地）：
- Δt ≤ 2s：规则原始强度；
- 2s < Δt ≤ 10s（正常带）：硬规则降为 γ_soft；
- 10s < Δt ≤ 30s（扩展带）：一律轻罚 γ_extended(0.9)；
- 窗口内中间调整次数 > 4（你在连续拖动寻值，校准 Q4 确认中间全是噪声）→ 降为 γ_soft。
- **所有纠正一律写锚点**（静止值 user_L）：锚点是设备映射收敛的原料，比置信度降级更值钱。

四象限落位：场景 A 全部 `quadrant=false_alarm`（出手了你不领情）；B=`correct_detection`；C=`missed_need`。

## 4. 输出契约（对齐 A1）

`Verdict` 是纯函数 `attribute(case) -> Verdict` 的返回，字段即 A1 的列：

- `reaction ∈ {accept, correct, ignore, missed_need}`（reject 保留给显式拒绝，如点了气泡"不要"）
- `quadrant ∈ {correct_detection, false_alarm, missed_need, non_response, NULL}`
- `gamma / lambda_up`：交给学习器执行棘轮（学习器不自带判断）
- `anchor_loudness`：写 `audio.device_map` 的锚点
- `rule`：**规则编号（如 A1/N2/C1），进 evidence——每条记忆都能引用"判它用的是哪条规则"**
- `evidence.detail` JSON（A1 留的口子在此定义）：

```json
{
  "delta_s": 6.2, "knob": "master", "dir": "down",
  "from_l": 0.45, "to_l": 0.60, "mag": 0.15,
  "meter": {"mean": 0.31, "peak": 0.55, "active_frac": 0.80},
  "foreground": "msedge.exe", "rule": "A2", "burst_count": 2
}
```

## 5. 防污染护栏（五条，均为硬规则）

1. **宁可不学，不可学错**：任何歧义场景判 ignore（如 session 调整、幅度过小、窗口外）；
2. **纠正风暴保护**：连续拖动只认静止值，中间值全部丢弃；
3. **连续两次纠正 → 自动降级只建议 + 面板标红**（A1 生命周期已有，由学习器执行）；
4. **单日纠正上限**：某偏好当日纠正 ≥3 次即冻结当日置信度调整（防异常日毁掉长期学习）；
5. **dry_run 不产生纠正**：没执行就没有可纠正对象——dry_run 周的调整一律按场景 C 学习。

## 7. 对 A1 的一处修订

`action_log.exec_mode` 增加 **`none`**：触发事件命中但决策为"不出手"也落台账（含命中信念但置信不足、
无适用信念两种）——没有这一行，场景 C 的 missed_need 就没有可挂靠的记录，四象限会缺一角。

## 8. 传感器反推（Phase 1 音量技能的前置）

1. **音量观察传感器**：`OnPropertyValueChanged` 不能再整个丢弃——需识别 master/session、
   去抖（settle）、换算响度域后发 `audio.volume/changed` 事件（风暴问题在观察层解决，不进总线）；
2. **电平表受控采样器**：仅在归因窗口内以 2Hz 采样 `IAudioMeterInformation`，
   窗口结束即停——"触发全事件驱动，取证允许受控采样"的第一次落地；
3. 两者都挂在现有 STA 线程内，不加线程。
